Implementation notes

Boundaries first.

Paragraph → model

Input: “A workshop has €48,000 fixed costs. Each unit sells for €125 and costs €73 to make.”

Interpretation: fixed = 48,000; price = 125; variable = 73.

Check: authored code calculates 48,000 ÷ (125 − 73) = 924 units after rounding up.

Rule → boundary

Input: “Amounts of at least €10,000 require review.”

Interpretation: amount ≥ 10,000.

Check: boundary cases are 9,999.99; 10,000; and 10,000.01. The middle case must enter review.

Question → instrument

Input: an original question asking for a linear function from two points.

Proposal: show the points and a movable slope triangle.

Check: exact rational arithmetic verifies both coordinates before the interaction is accepted.

Why GeoGebra is not the checker

The current API is excellent for construction and interaction. Input validation and exact affine comparison stay in small, testable modules. This prevents command-like input from reaching the applet and leaves the trainer functional when the remote runtime is unavailable.
